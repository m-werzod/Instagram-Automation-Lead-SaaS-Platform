# Platform audit — 2026-09-24

Pre-implementation audit for the seven-functionality upgrade (six existing groups + the new
**AI Video Editor**). Baseline commit `8b98b81`: **268 tests pass, `tsc --noEmit` clean, `eslint`
clean**, deployed at https://instagramaileads.vercel.app (Neon Postgres).

Method: eleven independent subsystem readers over `src/`, `prisma/`, `scripts/`, `tests/`, `docs/`,
each required to cite `path:line`; every claimed defect then handed to a separate adversarial
verifier told to refute it. **72 verdicts: 71 confirmed, 1 refuted** (the refuted one described a
missing attempts-cap in the job claim, which this session had already fixed by the time the verifier
read the file). Findings below are the confirmed set. This supersedes nothing in
`docs/AUDIT_2026-09-12.md` — that audit's gaps were implemented; these are the defects found *in*
that implementation.

## 1. Existing architecture

| Layer | Technology | Notes |
| --- | --- | --- |
| Web | Next.js 15 App Router, React 19, Tailwind 4 | `src/app/(dashboard)/*` control centre, 11 nav entries |
| API | Route handlers behind `route()` wrapper | zod-validated, audit-logged, RBAC-scoped |
| DB | PostgreSQL + Prisma 6 | 45 models, 14 migrations, tenant anchor = `InstagramAccount` |
| Auth | Custom cookie sessions, bcrypt cost 12 | OWNER / ADMIN / USER + `AccountAccess` |
| Queue | Postgres `FOR UPDATE SKIP LOCKED` | 14 job types; worker process or serverless cron drain |
| Meta | Raw REST via `graphCall` | Instagram Business Login + Facebook Login for ads |
| AI | Provider abstraction (REST) | Anthropic / OpenAI-compatible gateway / Google |
| Payments | Stripe hosted Checkout | platform fees only — never Meta ad spend |
| i18n | Dictionary-driven, cookie-persisted | **uz default**, en, ru |
| Deploy | Vercel (web) + GitHub Actions heartbeat (queue) | no resident compute |

**Tenant model.** Everything account-scoped hangs off `InstagramAccount`; `accountScope()` /
`assertAccountAccess()` are applied server-side in every account-bound route. Spot-checked across 20+
routes and found consistently enforced — this is the platform's strongest area.

## 2. What is genuinely working

Verified end-to-end, not merely present as UI:

- **Auth & RBAC** — pure, unit-tested decision functions; USER confined to granted accounts; last-OWNER
  protection; sessions revoked on password/role/suspension change; uniform login errors.
- **Meta OAuth** — both flows real; HMAC-signed state with 15-minute TTL; the admin callback requires
  the *same* browser session that started it; invite links are single-use, hashed, revocable.
- **Token security** — AES-256-GCM at rest, never serialized to the browser, `appsecret_proof` on calls.
- **Webhooks** — `X-Hub-Signature-256` mandatory and timing-safe, dedupe index, queued processing.
- **Queue** — atomic claims, exponential backoff, idempotency keys (defects in recovery, see §4).
- **AI runtime** — real guard chain (master switch → agent → conversation → 24h window → rate cap →
  working hours → output gate); tool permission tiers; usage accounting per call.
- **Knowledge base** — extract (PDF/DOCX/TXT/MD) → chunk → embed → retrieve, with an honest keyword
  fallback when no embedding provider is configured.
- **Lead flows & CRM** — one-question-per-step DM state machine, real source attribution, kanban,
  Telegram + email fan-out.
- **Campaigns** — full Marketing API chain created **PAUSED**, typed-name confirmation to activate,
  real reach estimate with honest `-1` handling, live spend/status sync.
- **Billing** — Stripe hosted Checkout (card data never touches this DB), off-session charges,
  signature-verified idempotent webhooks.
- **Publishing** — container → poll → `media_publish`, platform-side scheduling, retry, quota check.
- **Honesty** — no fabricated metrics anywhere in product code; unsupported Meta capabilities are
  refused with reasons rather than faked.

## 3. Confirmed defects, by severity

### High

| # | Defect | File | Effect |
| --- | --- | --- | --- |
| H1 | Webhook signatures verified only against the **Facebook** app secret, never the Instagram one | `src/app/api/webhooks/instagram/route.ts:42` | The primary product flow is Instagram Login, whose webhooks are signed with `META_INSTAGRAM_APP_SECRET`. Every real delivery is rejected as a bad signature. |
| H2 | Comment automations **double-fire** on webhook retry | `src/lib/queue/handlers.ts:238` | The message path dedupes on `Message.mid`; the comment path has no equivalent. Meta's at-least-once redelivery sends the commenter a second private reply/DM. |
| H3 | Stale jobs retry **forever with no backoff** and are never dead-lettered | `src/lib/queue/index.ts:112` | A killed job returns to FAILED with `runAt` untouched and no attempts cap, so it re-runs in a tight loop indefinitely. Fatal for minutes-long video renders. |
| H4 | Scheduled post stuck in `SCHEDULED` forever with no error | `src/lib/meta/publishing.ts:239` | `resolveAccess()` runs *before* the try block; a token failure throws past the status writer, so the post never publishes and never reports why. |
| H5 | Percent-based campaign fee **mixes currencies** | `src/lib/billing/pricing.ts` | A percent fee on a campaign budget denominated in one currency is charged in the platform's currency with no conversion or equality guard — arbitrary over/undercharge. |
| H6 | Comment-keyword lead delivery **advertised but not implemented** | UI strings vs. code | Three UI strings promise a comment code word starts the question flow; no code path does it. |

### Medium

Publishing/media: early-wake re-enqueue is a silent no-op due to an idempotency-key self-collision, so
an early-woken post never publishes; a cancel issued while a worker pass is in flight publishes anyway
and overwrites the status; `/r/[id]` returns 500 for Cyrillic/Uzbek filenames (Latin-1 header
encoding), breaking both the public link and Meta's attachment fetch; Story insights always fail
silently because the FEED metric set is requested for STORY media while the UI toasts success;
uploaded media accumulate in Postgres forever with no list/delete/GC.

Messaging: a resource + caption send issues **two** private replies to one comment, but Meta allows
only one, so the caption send always fails; an admin's manual send claims implicit human takeover but
never actually pauses the AI; `CONVERSATION_HANDOFF` automations never fire on AI-initiated handoff;
conversation detail returns the **oldest** 200 messages, hiding the newest in long threads.

AI: the cost estimator bills `gpt-4o-mini` at `gpt-4o` rates (~16× overestimate) through a
`startsWith` ordering bug; network errors are marked non-retryable against the class's own contract,
so customers get the canned fallback instead of a retried real answer; knowledge upload extracts and
embeds **inline in the API route** with no duration budget and no reprocess path, so a large document
can be stuck in `PROCESSING` permanently; the default AI timeout chain (60s + one retry ≈ 123s)
exceeds the 60s serverless drain, killing the invocation mid-job and risking double-sent DMs.

Meta: batched webhook deliveries can be silently dropped when the 500-char dedupe key truncates
mid-event; the 60-day **ads** token expiry is unmonitored (the refresh sweep filters `kind:'user'`
only) so campaigns die silently; permission sync is grant-only, so the capability matrix keeps
claiming scopes the user has revoked.

Billing/campaigns: locally archiving a campaign that is ACTIVE in Meta abandons a still-spending
campaign; an off-session charge with an unknown outcome can double-charge and wedges the row in
`PROCESSING`; cancelling a schedule-generated payment permanently halts that recurring schedule.

Queue/ops: no timeout on any outbound fetch or job execution, so one hung socket stalls the queue;
`lead.process` retry double-sends Telegram and email; unconfigured SMTP turns every lead into a DEAD
job and flips health to unhealthy; the health endpoint cannot detect that nothing is draining.

Frontend: the ad-preview iframe combines `allow-scripts` + `allow-same-origin` on `srcDoc`
(self-defeating sandbox); failed primary loads leave a permanent "Loading…" with no error state or
retry; there are **no** `error.tsx` / `not-found.tsx` boundaries anywhere.

Lead button: deleting a flow bricks the builder (dangling `leadFlowId`, save 500s forever);
`PATCH /api/cta/[id]` does not validate flow ownership across accounts; disabling the Lead Button
404s the landing page while linked ACTIVE campaigns keep spending on an ad pointing at it.

### Low (selected)

`clientIp()` trusts the first client-controllable `x-forwarded-for` entry; `CRON_SECRET` is accepted
in the URL query string; the post-login redirect check is bypassable with a backslash (open redirect);
OAuth state HMAC uses non-constant-time comparison; an admin-supplied `validationRegex` runs against
public input unanchored and untimed (ReDoS); logger redaction stops below depth 4; the declared
`API_WRITE` rate limit is never applied to any route; search inputs fire one request per keystroke.

### Cross-cutting

**The in-memory rate limiter is per-process.** On Vercel each lambda instance keeps its own buckets, so
login brute-force protection, the public lead-flow flood guard, the invite-token probe throttle, and
the new account-wide automation rate limit are all far weaker than they appear. Flagged independently
by five of the eleven auditors.

## 5. Security concerns

Ranked: (1) the ineffective distributed rate limiting above; (2) the Instagram webhook secret
mismatch, which is both a defect and a signature-validation gap; (3) client-controlled IP trust;
(4) admin-supplied regex executed on public input; (5) the self-defeating preview sandbox;
(6) `CRON_SECRET` in query strings landing in access logs. No secret leaks into client bundles were
found; tokens are encrypted at rest and redacted in logs.

## 8. Deployment reality that constrains the video editor

- Vercel functions cap at 60s (`maxDuration`), the cron drain stops claiming at ~52s, and the
  filesystem is read-only except ephemeral `/tmp`. **FFmpeg cannot run there.**
- Request bodies cap at 4.5 MB; the app enforces 4 MB. Real video needs either direct-to-storage
  client uploads or a self-hosted ingest route.
- `MediaAsset.data` is Postgres `bytea` served by loading the whole buffer with no HTTP Range support.
  Unsuitable for video playback or scrubbing.
- Meta must be able to **download** a finished render from a public HTTPS URL for the whole processing
  window.

Consequence, and the core architectural decision of this upgrade: video work runs in a dedicated
**`video` job lane** that only a resident worker with FFmpeg claims. The serverless drain is
structurally prevented from claiming it, and the UI reports the lane offline rather than pretending
a render is progressing.

## 9. Recommended implementation sequence

1. **Queue hardening** — lanes, leases with heartbeat renewal, per-job timeouts, correct
   dead-lettering. *(Everything long-running depends on it.)*
2. **Meta core fixes** — Instagram webhook secret, comment dedupe, dedupe-key overflow, ads-token
   expiry monitoring, permission revocation.
3. **Publishing fixes** — stuck `SCHEDULED`, early-wake no-op, cancel race, non-Latin filenames,
   Story insights, media lifecycle.
4. **CRM & lead button** — attribution gaps, flow-deletion integrity, cross-account flow validation,
   pagination, tags/follow-up, the missing comment-keyword path.
5. **AI & knowledge** — cost table, retry semantics, background document processing, timeout budget,
   prompt-injection framing for retrieved chunks, multilingual prompts.
6. **Billing & campaigns** — currency guard, archive guard, charge idempotency, schedule continuity,
   review-state surfacing.
7. **Security** — distributed rate limiting, IP trust, redirect and regex hardening, sandbox.
8. **Video editor foundation** — storage drivers, models, upload, probe, job runner.
9. **Video editor features** — audio mixing, subtitles, sample analysis, chat assistant, export.
10. **Publishing bridge** — export → existing publish pipeline.
11. **QA, security review, documentation.**
